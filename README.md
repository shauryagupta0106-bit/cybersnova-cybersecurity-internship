# CyberSNova Cybersecurity Internship

**Cybersecurity Projects | Technical Documentation | Security Testing Evidence**

## Overview

This repository contains the project documentation, testing evidence, screenshots, observations, and consolidated report prepared as part of the CyberSNova Cyber Security Internship.

The repository is organized into six projects covering network reconnaissance, web directory enumeration, login traffic analysis, web vulnerability assessment, OWASP Juice Shop security testing, and PortSwigger Web Security Academy labs.

The purpose of this repository is to document the testing process, record evidence-based observations, identify potential security weaknesses, and present appropriate remediation recommendations.

## Project Index

### Project 1: Network Reconnaissance and Service Enumeration

**Objective:** To perform authorized network reconnaissance and service enumeration and document the results.

**Activities:**
- Identify the authorized target and testing scope.
- Perform network scanning and port enumeration.
- Record scan results and observed network responses.
- Document findings and limitations.

**Deliverables:** Project documentation, scan evidence, observations, and recommendations.

### Project 2: Hidden Directory and File Enumeration

**Objective:** To investigate web directory and file discovery techniques within the authorized testing environment.

**Activities:**
- Perform directory and file enumeration.
- Record discovered paths and server responses.
- Review observations for potential information exposure.
- Document results and recommendations.

**Deliverables:** Enumeration evidence, documented observations, and recommendations.

### Project 3: Login Traffic Analysis

**Objective:** To examine login-related network traffic and document the behavior observed during analysis.

**Activities:**
- Inspect captured network traffic.
- Identify relevant login requests and associated responses where available.
- Review request methods, URLs, and content types.
- Document findings supported by the available packet evidence.

**Deliverables:** Traffic analysis documentation, relevant screenshots, and observations.

### Project 4: Basic Web Vulnerability Assessment

**Objective:** To conduct basic security checks against the authorized web application testing environment.

**Activities:**
- Perform web application reconnaissance and security checks.
- Use relevant tools to identify potential security issues.
- Review scanner output and application behavior.
- Document observations, evidence, limitations, and remediation recommendations.

**Deliverables:** Assessment documentation, relevant tool output, screenshots, and recommendations.

### Project 5: OWASP Juice Shop Security Assessment

**Objective:** To assess the security of the OWASP Juice Shop training application in an authorized lab environment.

**Activities:**
- Investigate relevant web application security weaknesses.
- Record testing procedures and observed application behavior.
- Preserve supporting evidence for validated findings.
- Document potential impact and remediation guidance.

**Deliverables:** Security assessment documentation, available testing evidence, observations, and remediation recommendations.

**Evidence note:** Only vulnerabilities successfully reproduced and supported by evidence should be reported as confirmed findings. Areas investigated without sufficient proof should remain identified as unconfirmed or requiring further validation.

### Project 6: PortSwigger Web Security Academy Labs

**Objective:** To practice web application security testing through authorized PortSwigger Web Security Academy labs.

**Activities:**
- Work through selected labs in the training environment.
- Document the objective and testing approach for each lab.
- Record evidence of completion where available.
- Summarize relevant security concepts and defensive recommendations.

**Deliverables:** Lab documentation, supporting screenshots, and recorded completion evidence.

## Documentation and Evidence

Project documentation is intended to describe the testing objective, methodology, observations, supporting evidence, limitations, and recommendations.

Screenshots and tool outputs should correspond to the actual tests performed. Potential security issues identified by automated tools should be reviewed before being classified as confirmed vulnerabilities.

No result should be interpreted as proof of a vulnerability unless the available evidence supports that conclusion.

## Security and Ethical Considerations

All testing activities should be conducted only on systems and applications for which authorization has been granted, including designated training environments.

- Respect the defined testing scope.
- Avoid unauthorized access or disruption.
- Protect credentials, session tokens, personal information, and other sensitive data.
- Do not publish confidential information or sensitive raw traffic captures.
- Report findings accurately and distinguish verified results from unconfirmed observations.
